# M2 動作確認手順

- 対象：M2（ログイン・ユニフォーム・集合写真とロゴ・提出・地区学連の承認と差し戻し・締切後のロック・申込書の印刷）
- 作成日：2026年11月21日

確認の方法は2つあります。

| | デモ版 | 本番版 |
|---|---|---|
| 開き方 | 共有されたデモのリンク | Vercel の公開URL（docs/08 の設定後） |
| データ | その端末のブラウザの中だけ | Supabase（本物のデータベース） |
| 役割の切り替え | 画面上部の「チーム担当者／地区学連／事務局」で自由に切り替え | ログインしたメールアドレスの登録内容で決まる |
| 向いている確認 | 画面の流れ・文言の確認 | 権限（見えてはいけないものが見えないか）・メールの確認 |

---

## A. デモ版で流れを確認する

サンプルとして、東北地区に3大学（サンプル大学・杜の都大学・北上川大学）、関東地区に1大学（武蔵野テスト大学）が入っています。

### 1. チーム担当者：入力して提出する
1. 「チーム担当者」で開き、トップの「やることリスト」を確認します。M1の項目に加えて「ユニフォーム」「集合写真・ロゴ」「最終確認・提出」が増えています。
2. 「基本情報」で連絡先・登録番号を入れます。
3. 「選手名簿」で、写真のない選手に顔写真を入れます（未成年の選手は同意書の確認にもチェック）。
4. 「ユニフォーム」で、CP用・GK用の濃色・淡色の色名を入れます。1着に「協賛企業名入り」をチェックすると、当日現金払いの金額が表示されます。
5. 「集合写真・ロゴ」で画像を入れます。集合写真は短い辺が1200px以上必要です（小さい画像は理由つきで断られます）。
6. 「最終確認・提出」を開きます。直す項目が残っていると提出ボタンが出ません。すべてそろうと、確認のチェックを入れて「提出する」を押せます。
7. 提出後、選手を開くと「**変更できません：提出済みのため…**」と表示され、保存ボタンが消えることを確認します。
8. 「申込書を表示・印刷する」で、様式Ⅰ（参加申込書）と様式Ⅲ（引率責任者届出書）が表示されます。大学角印の欄があることを確認してください。
   - デモ版では印刷ボタンが動かないことがあります。本番版では印刷・PDF保存ができます。

### 2. 地区学連：確認して差し戻す・承認する
1. 上部の「地区学連」に切り替えます。東北地区のチームだけが表示され、**関東の武蔵野テスト大学は表示されない**ことを確認します。
2. 先ほど提出したサンプル大学を開き、コメントを空のまま「差し戻す」を押すと「差し戻しの理由を入力してください」と出ることを確認します。
3. コメントを書いて「差し戻す」を押します。
4. 「チーム担当者」に戻ると、トップに**差し戻しの理由**が赤く表示され、再び入力できるようになっていることを確認します。もう一度提出します。
5. 「地区学連」で再提出されたチームを「承認する」を押し、「原本の到着を記録する」も押します。

### 3. 事務局：全体の確認・ロック解除・担当者の登録
1. 「事務局」に切り替えます。全地区のチームが表示され、地区・状態で絞り込めることを確認します。
2. 地区承認済のチームを開き「事務局確認済にする」を押します。
3. 「事務局の操作」で、登録番号の確認チェックと、締切後のロック解除（日付と理由が必須）を試します。
4. 「大学・担当者の登録」で、大学を登録し、その大学の担当者（メールアドレス）を登録して「招待メールを送る」を押します（デモ版では実際には送られません）。

## B. 本番版で権限とメールを確認する（docs/08 の設定後）

本物のメールアドレスが3つ以上必要です（個人のGmailなどで構いません）。

1. 事務局としてログインし、「大学・担当者の登録」で次を登録します。
   - 大学：「テスト大学」（東北地区）
   - 担当者①：メールアドレスA／チーム担当者／テスト大学
   - 担当者②：メールアドレスB／地区学連／東北
2. それぞれ「招待メールを送る」を押し、**日本語のメール**が届くことを確認します。
3. 別のブラウザ（またはスマホ）でAとしてログインし、テスト大学の男子チームを作って入力・提出します。
4. Bとしてログインし、テスト大学が見えて、承認・差し戻しができることを確認します。
5. **登録していないメールアドレス**でログインすると、「このメールアドレスは登録されていません」と表示され、何も見えないことを確認します。
6. 確認が終わったら、事務局の画面でテスト用の担当者を削除してください（テスト大学のデータの削除方法は M4 で追加します）。

## ご意見をいただきたい点
- 申込書（様式Ⅰ・Ⅲ）の項目と体裁で、全日本学連に提出できそうか
- 差し戻し・承認の流れは、地区学連の実際の運用と合っているか
- ログインメールの文面はわかりやすいか

## 技術メモ（エンジニア向け）
| 項目 | 内容 |
|---|---|
| データベースの設計 | `supabase/migrations/20261121000000_init.sql`（表・RLS・提出/承認の関数・監査ログ・Storage） |
| データベースのテスト | `supabase/tests/run.sh`（手元の PostgreSQL で権限・流れを41項目確認） |
| 画面とデータの窓口 | `src/lib/store.ts`（共通）、`demoStore.ts`（デモ）、`liveStore.ts`（Supabase） |
| ログイン | メールのリンク（implicit フロー）または確認コード（数字）。パスワードなし |
| ロック | 締切日時・状態・事務局のロック解除期限で判定（画面とデータベースの両方） |
